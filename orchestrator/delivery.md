# Finish

- The Delivery Task delivers per `delivery.mode`; for `branch`, push only if `delivery.push`. Run `orca worktree set --pr <n>` when applicable and move the card (`orchestrator/start.md` "Board mapping").
- Tell the PO: link or branch, summary, risks, `human_only` steps left, (maintenance) the fix report draft for G-Reply.
- After Gate 2, close the session (`roles/orchestrator.md` "Every turn").
- After merge, delete `.team/<feature>/` when closing the Run; keep `.team/carry-over.md` and `.team/research/`.
- A new feature request while a Run waits at Gate 2: ask whether to merge first and start it on a fresh branch (recommended: one Gate 2 per capability) or fold it in; then ask the new scope questions one at a time.
- An older Run waiting only at Gate 2: offer approve, leave pending, or close it, in the same question as the new work.
- Gate 2 open while the PO tests: one question with "merge now" / "still testing" plus any open reviewer choice; "merge now" counts as the PO's merge request.
- `pr` mode: the Delivery Engineer runs `gh pr create --draft`, then the Orchestrator runs `orca worktree set --pr <n>`.
- Before any push, inspect `git show --stat` for every commit since the last review. Commits added after the last review get a scoped review plus Anti-AI; docs-only commits get a scoped review too.
- **Merge on request:** the PO's explicit "merge X" overrides `human_only` for that one branch. Merge on approval; report the pushed range and migrations, then move the card to `completed`. Offer CI watching and smoke tests once; never start them unasked.
- After a parallel Run reaches Gate 2, merge it into the feature or named branch only when no Reviewer is reading that branch. Resolve conflicts in a fast Builder Task, rerun verify, close its terminal, and move its card to `completed`. Add its leftover Should fix to the feature's fix round; the PO tests and merges once.
- Never leave conflict markers in a checkout running the PO's dev server. Dry-run `git merge-tree --write-tree --name-only`, resolve conflicts in the child worktree, then fast-forward.
- **Carry-over:** Should fix items left at merge go to `.team/carry-over.md`, one numbered line each (file:line, the fix). The next feature Run's Tech Lead reads it and plans the items as their own slice (no Tech Lead: the Builder's first slice, one `fix:` commit); items for a later capability are named at Gate 1. After that merge, rewrite the file with only what is still open.
- **Run cleanup:** `worker-release --dispatch <id>` each settled worker in `worker-list --run <id> --terminal-state retained|reclaimable` (on `release_pending`/`release_unknown` follow the receipt; skip PO-owned or unproven terminals), then `terminal close` the DEV pane and the Orchestrator mailbox.
- **Cleanup** ("merge everything into main", "clean up"): check each branch with `git merge-base --is-ancestor <branch> main`, then list the cleanup and get one OK (irreversible): the PO's checkout to `main` (`git pull --ff-only`) once no dev server runs from a worktree, `orca worktree rm --worktree path:<wt> --delete-branch` per delivered worktree, `git branch -d` for merged branches without one, `git worktree prune`, the Runs' `.team/` scratch and spec scratch deleted; keep `.team/config.yaml` and `.team/carry-over.md`. Stopping a worktree's own dev server is part of the PO's go; leave other projects' servers and tunnels running and name them.
